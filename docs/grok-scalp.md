# GROK SCALP — موتور جامع سیگنال‌دهی اسکالپینگ کریپتو

> تحلیل الگوریتمی، نه توصیه مالی. هیچ سفارشی به صرافی ارسال نمی‌شود و هیچ کلیدی برای معامله لازم نیست.

GROK SCALP یک موتور سیگنال‌دهی است که برای تایم‌فریم‌های کوتاه (۱ تا ۳۰ دقیقه) ساخته شده و
ساختار بازار، دیتای مشتقات، اوردرفلو، سنتیمنت و اسکرین‌شات چارت را در یک «کارت سیگنال» جمع می‌کند.
موتور به یک استراتژی قفل نیست: اول رژیم بازار را تشخیص می‌دهد و بعد وزن خانواده‌های شواهد را
بر اساس همان رژیم تغییر می‌دهد.

---

## ۱. نصب و اجرا

هسته موتور فقط با کتابخانه استاندارد پایتون کار می‌کند (پایتون ۳.۱۰+). برای داشبورد:

```bash
pip install -r requirements-scalp.txt
```

### کارت سیگنال در ترمینال

```bash
python -m grokscalp --symbol BTCUSDT --tf 5m                 # داده شبیه‌ساز (آفلاین)
python -m grokscalp --symbol SOLUSDT --tf 15m --lang en
python -m grokscalp --symbol ETHUSDT --tf 5m --live          # داده عمومی بایننس
python -m grokscalp --symbol BTCUSDT --tf 5m --image chart.png
python -m grokscalp --symbol BTCUSDT --tf 5m --json           # خروجی ماشین‌خوان
```

### داشبورد Streamlit

```bash
streamlit run grokscalp/ui/streamlit_app.py --server.address 0.0.0.0
```

### اسکن بازار و اعتبارسنجی

```bash
python -m grokscalp --scan BTCUSDT ETHUSDT SOLUSDT --tf 5m
python -m grokscalp --backtest --symbol BTCUSDT --tf 5m
python -m grokscalp --backtest --symbol BTCUSDT --tf 5m --live --calibrate   # نوشتن config/calibration.json
```

  engine.py          خط تولید: اسنپ‌شات → شواهد → تصمیم → کارت
  backtest.py        اعتبارسنجی واک‌فوروارد و کالیبراسیون احتمال
  data/synthetic.py  شبیه‌ساز رژیم‌محور و قطعی (بدون شبکه)
  data/binance.py    اندپوینت‌های عمومی بایننس/کوین‌گکو/ترس‌و‌طمع/فرانکفورتر

  render/charts.py   چارت Plotly با نواحی ساختاری و سطوح معامله
  ui/streamlit_app.py داشبورد کامل

## ۳. موتور چطور تصمیم می‌گیرد؟

### گام ۱ — رژیم بازار

روی تایم‌فریم بالاتر (۱ ساعته در دسترس یا خود تایم‌فریم) محاسبه می‌شود:

| رژیم | شرط تقریبی | پلی‌بوک |
| --- | --- | --- |
| روند صعودی/نزولی | ADX ≥ ۲۴ + شیب EMA + جهت DI | ادامه روند، خرید/فروش پولبک |
| رنج | ADX < ۲۱ | بازگشت به میانگین بین لبه‌ها |
| نوسان بالا | ATR یا عرض باند در صدک > ۸۵ | صبر برای سوییپ و بازپس‌گیری، نصف کردن حجم |
| فشردگی | عرض باند < صدک ۲۸ | شکار بریک‌اوت نکن، ریتست بعد از انبساط |
| کم‌عمق | حجم < ‎−۱.۳σ و ATR پایین | ورود نکن |

### گام ۲ — یازده خانواده شواهد

هر شاهد یک شیء `Evidence` است: کد، خانواده، جهت (+۱/−۱/۰)، وزن، قدرت و توضیح.
هیچ عددی از هوا نمی‌آید؛ کارت همه شواهد را چاپ می‌کند.

| خانواده | چه چیزی می‌بیند |
| --- | --- |
| **SMC/ICT** | BOS/CHoCH (با تأخیر تأیید، بدون ری‌پینت)، اردربلاک و FVG با درصد پر شدن، پول‌های نقدینگی BSL/SSL، سوییپ استاپ، OTE ۶۱.۸–۷۹٪، پریمیوم/دیسکانت، خط روند |
| **MTF** | جهت ۱۵m/۱h/۴h با وزن نزولی نسبت به فاصله |
| **DERIV** | CVD و واگرایی آن، OI با تفسیر چهارگانه (پول تازه/اسکوییز/فشار شورت/لیکویید لانگ)، فاندینگ و صدک آن، عدم‌تعادل اردربوک، خوشه‌های لیکوییدیشن، پرینت نهنگ، نسبت لانگ/شورت |
| **VSA/Wyckoff** | Spring، Upthrust، Stopping Volume، No Demand/Supply، تلاش در برابر نتیجه، فاز انباشت/توزیع |
| **IND** | واگرایی RSI/MACD، کراس هیستوگرام، ریبون EMA، بولینگر و اسکوییز، استوکاستیک، ایچیموکو، VWAP، ADX/DI، کندل حجمی |
| **VP** | POC/VAH/VAL و پذیرش قیمت داخل یا خارج ارزش |
| **PATTERN** | الگوهای کندلی، هارمونیک XABCD، دوقلو، مثلث، بریک‌اوت حجمی |
| **MACRO** | BTC، دامیننس USDT، شاخص دلار |
| **SENTIMENT** | ترس و طمع، تن اخبار، رویداد کلان نزدیک |
| **VISION** | روند، الگو، حمایت/مقاومت خوانده‌شده از تصویر چارت |
| **SESSION** | کیل‌زون لندن/نیویورک/آسیا و کیفیت نقدینگی |

### گام ۳ — جمع وزنی

```
مشارکت هر شاهد = وزن × قدرت × اعتبار خانواده × ضریب رژیم
لبه  = (خریدار − فروشنده) / (خریدار + فروشنده) × min(1, مجموع/۳)
تضاد = min(خریدار, فروشنده) / max(خریدار, فروشنده)
احتمال = 0.5 + 0.30 × tanh(1.25 × لبه)   ← سپس با کالیبراسیون بک‌تست تنظیم می‌شود
```

### گام ۴ — دروازه‌ها (چرا اکثر مواقع WAIT است)

سیگنال فقط وقتی صادر می‌شود که **همه** شرایط برقرار باشند: حداقل ۴ شاهد، لبه ≥ ۰.۱۶،
تضاد < ۶۲٪، مخالفت شدید تایم‌فریم بالاتر نباشد، فاندینگ در جهت معامله اشباع نباشد،
اسپرد بد نباشد و رویداد کلان تا ۳۰ دقیقه آینده نباشد. اگر یکی بلوکه کند، کارت `WAIT`
با فهرست دقیق دلایل و «شرط فعال شدن مجدد» چاپ می‌شود.

### گام ۵ — ریسک

- **ورود**: نزدیک‌ترین ناحیه ساختاری معتبر (OB/FVG/OTE/S-R) در سمت معامله؛ در غیر این صورت مارکت با هشدار «ریسک تعقیب».
- **استاپ**: پشت ناحیه ابطال و سوئینگ + ۰.۳۵×ATR، محدود به سقف درصدی هر تایم‌فریم.
- **اهداف**: تلاقی R:R پایه (۱.۴/۲.۶/۴.۲) با پول نقدینگی، VAH/VAL/POC و خوشه لیکوییدیشن.
- **اهرم**: از فاصله استاپ و درصد ریسک حساب مشتق می‌شود (`notional = ریسک / درصد استاپ`)،
  سپس به سقف تایم‌فریم و شرط «لیکوییدیشن حداقل ۳ برابر دورتر از استاپ» محدود می‌شود.
- **مارجین**: `notional / leverage / equity`؛ در کارت هم ریسک و هم مارجین گزارش می‌شود.

## ۴. کالیبراسیون: احتمال از کجا می‌آید؟

```bash
python -m grokscalp --backtest --live --symbol BTCUSDT --tf 5m --calibrate
```

بک‌تست واک‌فوروارد موتور را بار‌به‌بار روی تاریخچه اجرا می‌کند (فقط کندل‌های گذشته را می‌بیند)،
سفارش‌های لیمیت را با شرط پر شدن در ۳ کندل می‌پذیرد و می‌سنجد **TP1 قبل از استاپ** خورده یا نه.
خروجی: نرخ برد، انتظار R، پروفت فاکتور و تفکیک بر اساس رژیم/سشن/خانواده. اختلاف نرخ واقعی با
میانگین احتمال مدل، به‌صورت آفست محدود (±۸ واحد) در `config/calibration.json` ذخیره می‌شود.

> روی داده شبیه‌ساز، بک‌تست فقط «سیم‌کشی» را تأیید می‌کند؛ برای اعداد معنادار باید روی داده واقعی اجرا شود.
> در تست فعلی، نرخ برد شبیه‌ساز پایین است و موتور هم به همین دلیل بیشتر WAIT می‌دهد — این رفتار درست است.

## ۶. منبع داده

- **آفلاین (پیش‌فرض)**: شبیه‌ساز قطعی با تغییر رژیم، پاهای جابه‌جایی، سوییپ نقدینگی و حجم متناسب.
  همیشه کار می‌کند، تست‌ها و دمو را تکرارپذیر می‌کند و همه تایم‌فریم‌ها به یک قیمت پایانی می‌رسند.
- **زنده (`--live`)**: `fapi.binance.com` برای کندل/فاندینگ/OI/نسبت‌ها/عمق/معاملات،
  CoinGecko برای دامیننس، alternative.me برای ترس و طمع، Frankfurter برای DXY،
  faireconomy برای تقویم اقتصادی و (اختیاری) CryptoPanic برای اخبار. هر بخشی که نیاید،
  با یادداشت در کارت حذف می‌شود؛ اگر کل شبکه بسته باشد، شبیه‌ساز جایگزین می‌شود.

**محدودیت صادقانه:** بایننس دیگر `forceOrders` عمومی ندارد؛ نقشه لیکوییدیشن از نقدینگی
سوئینگ‌ها برآورد می‌شود و در کارت «برآوردی» علامت می‌خورد.

## ۹. دیپلوی روی Vercel (داشبورد وب)

Streamlit سرور دائمی می‌خواهد و روی Vercel اجرا نمی‌شود، پس نسخهٔ وب همان موتور است با یک
لایهٔ سبک:

```
public/index.html · style.css · app.js   →  داشبورد RTL (چارت canvas، شواهد، فلو، سنتیمنت، کارت)
api/index.py                             →  یک فانکشن پایتون: dispatch(method, path, body) + app فلاسک
grokscalp/**                             →  همان موتور، بدون تغییر و فقط با کتابخانه استاندارد
vercel.json                              →  تنظیم فانکشن و هدرها (کار ریوت را پرست فلاسک می‌کند)
scripts/vercel_dev.py                    →  اجرای محلیِ دقیقاً همان چیزی که دیپلوی می‌شود
```

Vercel برای اپ‌های پایتونی به یک «entrypoint» نیاز دارد، بنابراین `api/index.py` علاوه بر
`dispatch()` و `handler` استاندارد، یک `app = Flask(__name__)` هم می‌سازد: پرست فلاسک آن را
به یک فانکشن تبدیل می‌کند، مسیرهای `/api/*` را به همان `dispatch` می‌دهد و پوشهٔ `public/**`
را از CDN سرو می‌کند. `flask` تنها وابستگی دیپلوی است و در `requirements.txt` علامت خورده؛
مسیرهای CLI و Streamlit هیچ‌وقت آن را ایمپورت نمی‌کنند.

### API

| مسیر | توضیح |
| --- | --- |
| `GET /api/health` | نسخه، تایم‌فریم‌های مجاز، فهرست نمادها |
| `GET /api/symbols` | فهرست نمادهای پیش‌فرض |
| `GET /api/signal?symbol=BTCUSDT&tf=5m&live=1&equity=10000&risk=1.5` | کارت + ۲۰۰ کندل + خلاصهٔ فلو/سنتیمنت |
| `GET /api/scan?tf=5m&live=0` | اسکن چند نماد برای رتبه‌بندی |
| `POST /api/vision` | `{"image": "<base64 یا data URL>"}` → خوانش ساختاری تصویر |
| `POST /api/analyse` | همان سیگنال، به‌همراه تصویر چارت در بدنه |

`live=1` داده واقعی بایننس را می‌خواند؛ اگر شبکه بسته باشد موتور به شبیه‌ساز برمی‌گردد و
روی کارت اعلام می‌کند (`source`).

### اجرای محلی (بدون Vercel CLI)

```bash
python scripts/vercel_dev.py          # http://0.0.0.0:8000
curl -s localhost:8000/api/health
```

# نینیک سایت · Ninik Shop

فروشگاه فارسی و راست‌چین برای اسباب‌بازی، بازی آموزشی، پوشاک کودک و لوازم نوزاد. این پوشه مستقل از برنامهٔ Python موجود در مخزن است.

## اجرای پیش‌نمایش

با Node.js 22 در این پوشه:

```sh
npm ci
npm run preview
```

فروشگاه روی پورت ۳۰۰۰ و پنل روی `/admin` در دسترس‌اند. در پنل «ورود آزمایشی» را انتخاب کنید. در فروشگاه می‌توانید یک کالا را به سبد اضافه کنید و «ثبت سفارش آزمایشی» را بزنید؛ سپس سفارش را در تب «سفارش‌ها» ببینید. داده‌ها در `.data/demo.sqlite` ذخیره می‌شوند. پیش‌نمایش گذرواژه نمی‌خواهد، هیچ اطلاعات واقعی مشتری را ذخیره نمی‌کند، و هیچ پرداخت یا ارسالی انجام نمی‌شود. عکس‌ها و محصولات اولیه نمونه‌اند.

```sh
npm run build
npm test
```

آزمون‌ها نسخهٔ ساخته‌شده را با پایگاه دادهٔ موقت اجرا می‌کنند و ثبت سفارش، کنترل موجودی در سفارش‌های هم‌زمان، مدیریت و لغو سفارش، و فرادادهٔ سئو را می‌سنجند.

## انتشار فروشگاه واقعی

- در Vercel پروژهٔ **Next.js** بسازید یا پروژهٔ مورد تأیید را انتخاب کنید؛ **Root Directory** باید `ninik-site` و نسخهٔ Node.js برابر `22.x` باشد. برای استقرار مستقیم روی سرور Node، اجرای معمول `npm run build && npm start` است. در انتشار عمومی `NINIK_DEMO_MODE` را فعال نکنید؛ این حالت روی Vercel همواره غیرفعال است.
- یک PostgreSQL پایدار با اتصال TLS و پشتیبان‌گیری فراهم کنید. `DATABASE_URL` را در تنظیمات محرمانهٔ هاست قرار دهید؛ برنامه در اتصال اولیه جدول `ninik_store` را می‌سازد و به مجوز ایجاد جدول و خواندن و نوشتن آن نیاز دارد. SQLite فقط برای پیش‌نمایش یا سرور Node تک‌نمونه با حجم دیسک پایدار (`NINIK_DATA_DIR`) است، نه Vercel.
- `NINIK_ADMIN_PASSWORD` و `NINIK_SESSION_SECRET` باید مستقل و تصادفی باشند. حداقل طول به‌ترتیب ۱۲ و ۳۲ نویسه است؛ آن‌ها را در Git، چت یا فایل عمومی قرار ندهید. قبل از انتشار، ورود مدیریت و پشتیبان‌گیری را آزمایش کنید و برای ورود و ثبت سفارش محدودیت نرخ در سطح هاست بگذارید.
- در `/admin` عکس، نام، ردهٔ سنی، قیمت و موجودی واقعی را جایگزین دادهٔ نمونه کنید. کالاهای نمونهٔ اضافه را پنهان کنید. اطلاعات کسب‌وکار، سیاست حریم خصوصی، روش ارسال و بازگشت کالا را بازبینی کنید. هنگام آمادگی برای دریافت درخواست خرید، `NINIK_ENABLE_ORDERS=1` را بگذارید. این نسخه درگاه آنلاین ندارد. بدون ذخیره‌سازی، کاتالوگ فقط خواندنی است و پنل و ثبت سفارش واقعی غیرفعال‌اند.

## دامنه و Google Search Console

1. دامنهٔ متعلق به فروشگاه را به هاست اضافه کنید، DNS را طبق مقادیر اعلام‌شده توسط هاست تنظیم کنید و HTTPS عمومی بدون صفحهٔ ورود را بررسی کنید.
2. `SITE_URL` را روی مبدأ HTTPS دامنهٔ نهایی بگذارید. تا پیش از آن، صفحات `noindex` هستند و `robots.txt` جلوی خزیدن را می‌گیرد. بعد از تنظیم آن، صفحات عمومی canonical دارند، محصولات دادهٔ ساختاریافتهٔ Product دارند، و `/sitemap.xml` شامل صفحه‌های عمومی و کالاهای فعال است. پنل مدیریت و ثبت سفارش وارد نقشهٔ سایت نمی‌شوند.
3. مالکیت دامنه را در [Google Search Console](https://search.google.com/search-console) تأیید کنید (برای Domain property از DNS استفاده کنید؛ `GOOGLE_SITE_VERIFICATION` برای تأیید با متاتگ در URL-prefix property در دسترس است). نقشهٔ سایت را در بخش Sitemaps بفرستید و در URL Inspection برای صفحهٔ اصلی درخواست ایندکس کنید. [راهنمای گوگل](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl) دربارهٔ زمان و وضعیت بررسی توضیح می‌دهد. ایندکس‌شدن و رتبه در اختیار گوگل است.

## دموی عمومی بدون پایگاه داده

برای نمایش فروشگاه و پنل آزمایشی روی Vercel، `NINIK_BROWSER_DEMO=1` را تنظیم کنید و متغیرهای پایگاه داده و ثبت سفارش واقعی را خالی بگذارید. `/admin` ورود آزمایشی دارد؛ سفارش نمونه و ویرایش محصول در همان مرورگر ذخیره می‌شوند و برای بازدیدکنندگان دیگر قابل مشاهده نیستند. هیچ API مدیریتی باز نمی‌شود، اطلاعات واقعی مشتری وارد نمی‌شود و نسخهٔ نمایشی ایندکس نمی‌شود. برای فروش واقعی این حالت را بردارید و مراحل انتشار بالا را انجام دهید.
